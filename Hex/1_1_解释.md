# `Hex/1_1.asm` 反汇编解释文档

## 一、文件来源

`Hex/1_1.asm` 是由 `1.c` 编译生成的 ELF 可执行文件，再经过反汇编工具（如 `objdump -d`）反汇编得到的汇编代码。

对应的 C 源程序如下：

```c
#include <stdio.h>

int main() {
    int price = 0;

    printf("请输入金额（元）：");
    scanf("%d", &price);
    int change = 100 - price;
    if (price < 100) {
        printf("找您%d元。\n", change);
    }
    else {
        printf("100块不够\n");
    }
    return 0;
}
```

## 二、整体结构说明

反汇编文件并不是“一段连续的代码”，而是把整个 ELF 文件按字节流当作指令解码的结果。因此文件中包含以下几类内容：

| 区段 | 特征 | 说明 |
|------|------|------|
| ELF 头 / 程序头表 | 大量 `add byte ptr [rax], al`、`jg 0x47` 等 | 这些是文件头部的元数据字节，被强行解码成指令，并非真正可执行代码 |
| 填充区（padding） | 连续成百上千行 `add byte ptr [rax], al` | `0x00` 字节解码后就是 `add byte ptr [rax], al`，是节区对齐填充 |
| PLT / GOT 跳板 | `endbr64`、`push N`、`jmp qword ptr [rip + ...]` | 动态链接的函数桩，用于调用 `printf`、`scanf`、`puts` 等 |
| `_start` 入口 | `xor ebp, ebp`、`mov r9, rdx`、`call qword ptr [rip + ...]` | C 运行时入口，负责调用 `__libc_start_main(main, ...)` |
| `main` 函数 | `push rbp`、`mov rbp, rsp`、`sub rsp, 0x10` | 真正对应 C 源码逻辑的函数 |
| 只读字符串/数据 | `imul`、`outsb`、`insb` 等奇怪指令 | 字符串常量（如 `"请输入金额（元）："`、`"%d"`、`"100块不够\n"`）被解码成指令 |

> 结论：**真正需要关注的只有 `main` 函数**，其余大部分是数据被误读为指令的“噪声”。

## 三、关键区段解读

### 1. ELF 头部（被误读为指令）

文件开头：

```asm
jg 0x47
add r8b, byte ptr [rcx]
add dword ptr [rax], eax
add byte ptr [rax], al
...
```

这其实是 ELF 文件头（`7F 45 4C 46 ...` = `\x7FELF`）的字节被反汇编器当作代码解码的结果。`0x00` 字节统一解码为 `add byte ptr [rax], al`，所以会看到大量重复行。

### 2. `_start` 入口（C 运行时启动代码）

```asm
xor ebp, ebp            ; 清零 ebp，标记最外层栈帧
mov r9, rdx             ; rtld_fini
pop rsi                 ; argc
mov rdx, rsp            ; argv
and rsp, 0xfffffffffffffff0   ; 16 字节对齐栈
push rax
push rsp
xor r8d, r8d            ; fini = NULL
xor ecx, ecx            ; init = NULL
lea rdi, [rip + 0xca]   ; main 函数地址
call qword ptr [rip + 0x2ef3]  ; __libc_start_main(...)
hlt                     ; 不会执行到这里
```

这是 glibc 的标准启动流程：把 `main`、`argc`、`argv` 等参数传给 `__libc_start_main`，由它完成初始化后调用 `main`。

### 3. PLT 桩（动态函数调用跳板）

```asm
endbr64
push 0
jmp 0x1020              ; 跳到 PLT0（动态链接解析器）
```

每个外部函数（`printf`、`scanf`、`puts`、`__stack_chk_fail`）都有一个这样的桩，第一次调用时通过 GOT 跳到动态链接器解析地址，之后直接跳到函数本体。

### 4. `main` 函数（核心逻辑）

这是与 C 源码一一对应的部分：

```asm
endbr64
push rbp                       ; 保存旧栈帧
mov rbp, rsp                   ; 建立新栈帧
sub rsp, 0x10                  ; 分配 16 字节局部变量空间
mov rax, qword ptr fs:[0x28]   ; 读取栈金丝雀（stack canary）
mov qword ptr [rbp - 8], rax   ; 保存 canary
xor eax, eax

mov dword ptr [rbp - 0x10], 0  ; int price = 0;

lea rax, [rip + 0xe32]         ; rax = "请输入金额（元）："
mov rdi, rax                   ; printf 第 1 参数
mov eax, 0
call 0x10a0                    ; printf("请输入金额（元）：");

lea rax, [rbp - 0x10]          ; rax = &price
lea rdx, [rip + 0xe36]         ; rdx = "%d"
mov rsi, rax                   ; scanf 第 2 参数 = &price
mov rdi, rdx                   ; scanf 第 1 参数 = "%d"
mov eax, 0
call 0x10b0                    ; scanf("%d", &price);

mov eax, dword ptr [rbp - 0x10] ; eax = price
mov edx, 0x64                   ; edx = 100
sub edx, eax                    ; edx = 100 - price
mov dword ptr [rbp - 0xc], edx  ; int change = 100 - price;

mov eax, dword ptr [rbp - 0x10] ; eax = price
cmp eax, 0x63                   ; 比较 price 与 100
jg 0x122a                       ; if (price > 100) 跳到 else 分支

; ---- if 分支：price < 100 ----
mov eax, dword ptr [rbp - 0xc]  ; eax = change
lea rdx, [rip + 0xe0a]          ; "找您%d元。\n"
mov esi, eax                    ; printf 第 2 参数 = change
mov rdi, rdx                    ; printf 第 1 参数 = 格式串
mov eax, 0
call 0x10a0                     ; printf("找您%d元。\n", change);
jmp 0x1239                      ; 跳过 else 分支

; ---- else 分支：price >= 100 ----
lea rax, [rip + 0xe02]          ; "100块不够\n"
mov rdi, rax
call 0x1080                     ; puts("100块不够\n");

; ---- 函数收尾 ----
mov eax, 0                      ; return 0
mov rdx, qword ptr [rbp - 8]    ; 取出保存的 canary
sub rdx, qword ptr fs:[0x28]    ; 与原始 canary 比较
je 0x1252                       ; 相等则正常返回
call 0x1090                     ; 不相等则 __stack_chk_fail（栈溢出检测）
leave                           ; 恢复栈帧
ret                             ; 返回
```

## 四、与 C 源码的逐行对应关系

| C 源码 | 对应汇编 | 说明 |
|--------|----------|------|
| `int price = 0;` | `mov dword ptr [rbp - 0x10], 0` | 局部变量 `price` 存放在 `[rbp-0x10]` |
| `printf("请输入金额（元）：");` | `lea rax, [rip + 0xe32]; call 0x10a0` | 字符串通过 RIP 相对寻址取出 |
| `scanf("%d", &price);` | `lea rax, [rbp - 0x10]; call 0x10b0` | 把 `price` 的地址传给 `scanf` |
| `int change = 100 - price;` | `mov edx, 0x64; sub edx, eax; mov [rbp-0xc], edx` | `0x64 = 100`，`change` 在 `[rbp-0xc]` |
| `if (price < 100)` | `cmp eax, 0x63; jg 0x122a` | 用 `jg`（大于跳转）实现“小于则执行 if 体” |
| `printf("找您%d元。\n", change);` | `mov esi, eax; call 0x10a0` | `change` 通过 `esi` 传入 |
| `else printf("100块不够\n");` | `call 0x1080` | 编译器用 `puts` 优化了无格式化的 `printf` |
| `return 0;` | `mov eax, 0; leave; ret` | 返回值放在 `eax` |

## 五、几个值得注意的细节

### 1. 栈金丝雀（Stack Canary）

```asm
mov rax, qword ptr fs:[0x28]   ; 从 TLS 读取随机值
mov qword ptr [rbp - 8], rax   ; 放到栈上
...
sub rdx, qword ptr fs:[0x28]   ; 函数返回前校验
je 0x1252
call 0x1090                    ; __stack_chk_fail
```

这是 GCC 默认开启的 `-fstack-protector` 机制，用于检测栈缓冲区溢出。如果局部变量被越界写坏，canary 会改变，程序会调用 `__stack_chk_fail` 终止运行。

### 2. `else` 分支被优化为 `puts`

源码写的是 `printf("100块不够\n")`，但编译器发现格式串没有 `%` 转换说明符，于是自动替换成更高效的 `puts` 调用（`call 0x1080`）。这是 GCC 的常见优化。

### 3. 条件跳转方向

C 代码是 `if (price < 100)`，汇编却用 `jg`（jump if greater，大于则跳）跳到 else 分支。这是因为编译器把“条件成立执行 if 体”翻译成“条件不成立跳过 if 体”，即 `price > 100 → 跳到 else`，等价于原逻辑。

### 4. 大量 `add byte ptr [rax], al` 的由来

ELF 文件中有很多 `0x00` 字节（头部字段、节区对齐填充）。`0x00` 作为 x86-64 指令正好解码为 `add byte ptr [rax], al`（2 字节指令 `00 00`）。所以反汇编时会出现成百上千行这样的“假指令”，**它们不是真正的代码**，只是数据被误读的结果。

### 5. 字符串常量被误读为指令

类似 `imul ebp, dword ptr [rsi + 0x74], 0x4d547265`、`outsb`、`insb` 这些看起来很奇怪的指令，其实是字符串常量（如 `"GLIBC_2.34"`、`"libc.so.6"`、`"printf"`、`"scanf"` 等符号表/字符串表内容）被反汇编器解码出来的。它们位于 `.dynstr`、`.symtab`、`.rodata` 等节区。

## 六、总结

- `1_1.asm` 是 `1.c` 编译产物的完整反汇编，**真正有意义的代码只有 `main` 函数那一小段**。
- 其余内容是 ELF 头、程序头表、PLT/GOT、字符串表、动态符号表等数据被强行当作指令解码产生的噪声。
- `main` 函数清晰地体现了：局部变量分配、`printf`/`scanf` 调用约定（RDI/RSI/EDX 传参）、算术运算、条件分支、栈保护，以及编译器对 `printf` → `puts` 的优化。
- 阅读这类反汇编文件时，应先定位 `main`（通常通过 `lea rdi, [rip + ...]` + `call __libc_start_main` 中的 `main` 地址，或直接搜索 `endbr64; push rbp; mov rbp, rsp` 的函数序言），再忽略其余噪声。
